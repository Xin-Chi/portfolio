Venom-Bot
LINE × Gemini Personal AI Chatbot

Personal Project | Jun 2026 – Jul 2026 (live, in daily use by a group of friends)
SUMMARY
  • Delivered end-to-end development and operations solo: architecture, deployment, post-launch debugging and iteration against multi-user testing
  • Handles 7 input types (text / stickers / images / audio / video / PDF / links) through one shared memory and input-guard layer
  • Iterated repeatedly on the persona prompt design, then ran prompt-injection security testing against the live bot
  • Hit 4 real engineering problems (free-tier sleep, mismatched platform limits, latent bugs, the wrong cost metric for PDFs) and solved every one with measured data rather than guesswork
Project Overview

Designed and shipped a LINE × Gemini chatbot, with a FastAPI backend deployed on Render. The work spans secrets management, deployment, post-launch debugging and the stability fixes that came out of multi-user testing. Every decision was driven by measured data and real bugs, not a plan on paper.

Debugging Log
①The free tier sleeps — and the fix had to be external
Render's free tier sleeps after 15 idle minutes, and a cold start takes roughly 60 seconds — longer than LINE's own reply window. A first-time message may well get no reply at all, which reads to the user as “the bot is broken.” The fix is something outside pinging it regularly to keep it awake, and that too had to stay inside a free tier. GitHub Actions was the first idea, until I checked the billing: every run counts as at least one minute, so pinging every 5–10 minutes burns about 4,320 minutes a month against a 2,000-minute free allowance, exhausted in roughly 14 days.
✓Switched to UptimeRobot: a free-tier ping every 5 minutes, well inside its allowance, no manual intervention, zero cost
②Two latent bugs that only multi-user testing could surface
A friend sent 30 images back to back, which exposed that a single failed message had no proper fault tolerance around it: one failure dragged the whole batch down and nothing got a reply. The same session revealed that the back-off logic for “calling Gemini too often” was written as global shared state, so one person spamming left everyone else on read.
✓Added fault tolerance so one failure can't affect other messages, and moved rate-limit state to per-user tracking. Neither bug was predictable in advance; only real users surfaced them
③What the platform accepts ≠ what the model can process
LINE lets users upload files up to 200MB, but Gemini accepts only 20MB of audio and 100MB of video. The two limits are completely asymmetric, so the gap had to be closed with my own guard layer. And which metric actually tracks cost — file size, duration or page count — differs by media type, so each one had to be verified separately.
✓Audio and video are now gated on the duration LINE already provides — three media types, three independently validated thresholds
④Capping PDFs by file size was measuring the wrong thing
I assumed file size would bound token cost. Testing said otherwise: a plain-text PDF of just 0.28MB and 300 pages consumed 160,168 tokens — 64% of the per-minute budget in a single request. File size and page count are simply not proportional.
✓Digging in showed Gemini bills PDFs at a flat 258 tokens per page. Gating on the actual page count via pypdf (6-page cap) is the metric that actually tracks cost
What These Four Problems Had in Common
None of them could be answered by reading documentation or trusting intuition. Each needed measurement, sometimes a careful controlled comparison, and the answer often contradicted my starting assumption outright.
Design Highlights
Structured Output: Reply and Meme Choice in a Single Call
Structured output lets Gemini return both the reply text and an optional meme ID in the same call, with no second request. Even when Gemini judges a meme to fit the moment, it is only attached 25% of the time — deliberately, so replies stay varied rather than predictable.
Iterating on Persona and Tone (Prompt Engineering)
The first persona was “a bit sharp,” and friends said it came across as aggressive; two rounds of tuning landed on “polite by default, occasionally sarcastic.” I added a rule to stay respectful when the author is mentioned, then found the model bringing the author up unprompted as a joke, which needed a further “never raise it yourself” correction. Every adjustment meant re-testing normal conversation, deliberate provocation, and author mentions to confirm the new tone had no unintended side effects.
Prompt Injection Self-Testing
Tested the live bot against the common techniques — leaking the system prompt, instruction override, breaking the length cap, baiting fabricated answers, and role-play jailbreaks. All were blocked; anything a user did manage to pressure out of it was invented, not the actual configuration or method.
